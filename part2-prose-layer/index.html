为什么#

人写的文稿 —— 教程、how-to、runbook、ADR —— 是软件知识库最古老的那一层，也是唯一机器没办法凭空生成的那一层。第二部分展示的是：文稿层参考实现如何让这一层可信、可搜、可自动化，同时不把内容锁死在某个专有系统里 —— 以及如何让它随时间推移仍然正确。

第二部分在书里的位置#

第二部分是这本书里****两个平行的“层”部分中的第一个。第四部分走的是同一个形状 —— 五章：选定一个承载层、把它的契约锤结实、在它之上跑一条流水线、把它暴露出去以便查询、**最后以一个运维模型收尾 —— 只不过应用对象是 代码 而不是 文稿 。第六部分随后展示这两层怎么协作**（一个同时读这两层的文档分层元组；一个把文稿段落和代码 embedding 融合在一起的检索面）。单读第二部分，你会得到一个站得住脚的文稿层知识库；第二、第四部分一起读，你会得到****第六部分用来变成一个懂代码的知识库的那块承载层；第七部分是对第二到第六部分所产出之一切的治理。

Part I       : the vocabulary (why a KB, what IR/RAG actually are, Diátaxis)
Part II      : the PROSE layer  — files → frontmatter → pipeline → search → op model    (this part)
Part III     : the AUTHOR layer — AI drafts, classifies, extracts, maintains, judges
Part IV      : the CODE  layer  — parse → embeddings → graph → hybrid retrieval → prompt
Part V       : the ops lifecycle — sync, eval, drift, rot (operational plumbing for Parts II and IV)
Part VI      : the hybrid layer — where prose and code meet
Part VII     : governance, trust, and outlook

文稿层的结构，被刻意地镜像到****第四部分的收尾里： 两边各四个角 ，这样这本书的第六、第七部分****就可以用同一套词汇讨论两层。 注意到这次镜像 ，是内化这个形状的最便宜的方法；下面的 §“How” 会把这次镜像显式命名出来。

是什么#

一个基于文件的 wiki（第 4 章），由 YAML frontmatter 加 footer 组成的双块「来源 + 评审」记录（第 5 章），分类流水线（第 6 章），发布与内存搜索（第 7 章），以及一套在底下的代码持续变化时、仍让文稿保持正确的运维模型（第 8 章）。

怎么做#

六章。第 4–7 章负责 把文稿收进来 。第 8 章用一个「四角」运维模型收尾：一份固定的页面集、一个元数据 footer、三级更新策略、以及校验闸。这四个角后面在第五部分以及第 25、29、30 章里被具体落地，和第四部分结尾的另一个「四角」（解析 / embedding / 图谱 / prompt）互为镜像。

阅读路径 —— 按你手头的问题挑一条#

第二部分有一千六百行。你不需要按次序读它。三条典型路径，已经覆盖了多数读者的目的：

  • “开会前只有 20 分钟，我想抓住核心论点。” 读第 4 章的开场钩子和 ## Why，再读第 8 章的 ## Why，然后读第 8 章的 ## 一页总览第二部分 —— 一张跳转清单。三页纸就把整个论点讲完了。细节以后再回来看。

  • “我正在搭工具链。” 按顺序读第 4 章 → 第 5 章 → 第 6 章，第一遍跳过 ## 竞品方案 表格。然后读代码引用：ch04/repository.go、ch05/frontmatter.go、ch06/pipeline.go。第 7 章略读即可；等你拿一个真实语料跑过一遍流水线、想搞清楚该执行哪些规则时，再回来看第 8 章。

  • “我已经有一个知识库了，正在做复盘。” 跳过各章的 ## Why 段，直接看： 第 6 章 §“LLM 分类在生产中怎么出错”、 第 7 章 §“小型搜索引擎在哪里失灵”、 第 8 章 §“这个模型不能解决什么”。把你在现实中见过的每一个症状和第 8 章的 Part II 检查清单对照；它会告诉你该精读哪一章。

这几条路径，就是这个部分被这样组织的原因：每一章都**自带一段自洽的开场、一份自洽的失败目录、以及一张自洽的“竞品方案”表 —— **这样从这个部分中途走进来的读者**不用按序读，**也能带走一套完整的思考单元。

示例#

用 CLI 对一个乱糟糟的 raw 文件夹跑一次端到端流程，产出一个干净的 wiki。完整的分步演示放在附录 A。

结论#

基于文件 + 由 Git 托管 + 流水线校验 + 有运维模型支撑 = 一个「行为像代码」的文稿层：可评审、可 diff、可自动化，而且过时与否是可审计的。
